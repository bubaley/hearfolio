# Организации (Hearfolio Cloud)

Приложение подключается к серверу Hearfolio Cloud команды (любой домен, self-hosted), загружает туда записи и показывает записи организаций. Контракт API — `cloud/docs/product.md`, раздел «API contract for the apps».

## Подключение

Настройки → «Облако» → адрес сервера. Приложение нормализует адрес (без схемы → `https://`; обычный `http://` разрешён только для localhost, частных IP и `.local/.lan/.test`), читает `/.well-known/hearfolio` и проверяет `product`, `api_version == 1` и `min_app_version` против версии приложения — при несовместимости показывается понятная причина («Обновите приложение» / «Сервер устарел»).

Вход — OAuth 2.0 authorization code + PKCE (S256), клиент `hearfolio-app`. Браузер открывает `{authorize_url}?client_id&redirect_uri&code_challenge&code_challenge_method=S256&state&device_name`. Ответ возвращается:

- deep link `hearfolio://oauth/callback` — Android, установленные сборки macOS (бандл `.app`), Windows/Linux, если схема зарегистрирована (single-instance передаёт URL запущенному приложению);
- иначе loopback `http://127.0.0.1:{port}/callback` — одноразовый слушатель на случайном порту (dev-запуски).

`state` проверяется, незнакомый или повторный — игнорируется; незавершённый вход живёт 15 минут и переживает пересоздание Android-активности (`flows.json`). Код обменивается на `Token`-токен; если сохранить его не удалось, токен сразу отзывается. Повторный вход того же аккаунта на тот же сервер заменяет подключение, а неудавшиеся из-за истёкшего доступа загрузки запускаются снова. Если в «Войти снова» вошёл другой аккаунт, создаётся новое подключение, а у старого удаляются зеркало, кэш аудио и токен; его незагруженные записи получают «Нет доступа к организации» с «Сохранить на устройстве» — к новому аккаунту они не уходят. Пропавший токен (например, сброс связки ключей) переводит подключение в «Нужно войти». «Отключить» отзывает токен (`/oauth/revoke`, без сети — только локально), удаляет его, зеркала и кэш аудио организаций этого подключения. Loopback-слушатель отвечает только на callback своего `state`, остальные запросы игнорирует и продолжает ждать; `error=access_denied` со своим `state` — отмена. Запросы к API не следуют редиректам на другой хост и с https на http.

Токены не попадают в WebView и логи. Desktop — системное хранилище через crate `keyring` (Keychain, Credential Manager, Secret Service): без мастер-пароля и дополнительного UI, в отличие от Stronghold. Если на Linux нет Secret Service, токен лежит в файле `0600`, а подключение помечено «Ключ в файле». Android — AES-256-GCM ключ Android Keystore (неэкспортируемый), в SharedPreferences только шифротекст; `scripts/prepare-android.mjs` (Android-проект генерируется и не хранится в репозитории) выключает Auto Backup (`android:allowBackup="false"`) и задаёт `MainActivity` режим `singleTask`, чтобы deep link возвращался в уже открытое приложение. Device-to-device перенос Android 12+ это не отключает, но ключ Keystore не переносится — приложение просто попросит войти снова.

## Куда записываем

Компактный выбор «Куда» на стартовом экране, в диктофоне и над кнопкой записи на телефоне: «На этом устройстве» или организация → проект (необязательно) → «Общая/Личная». Выбор запоминается. Запись и импорт файла в организацию сначала проходят обычное сохранение (сжатие WAV → AAC/FLAC, защита от сбоев), затем запись уходит в очередь загрузки и пропадает из локального архива: её аудио теперь принадлежит очереди. Локальная расшифровка для таких записей не нужна — расшифровывает сервер. Записи из плитки/ярлыка Android остаются локальными.

«Поделиться → Копировать в организацию» копирует локальную запись (локальная остаётся). Если есть расшифровка, она отправляется вместе с записью, и сервер не расшифровывает повторно.

## Очередь загрузки

Rust-воркер (`src-tauri/src/org/worker.rs`) обрабатывает `queue.json` по одной записи, от старой к новой. Состояния: В очереди → Загружается N% → (Завершаем) → Готово; Ждёт сети; Ошибка загрузки → «Повторить». После каждой подтверждённой части состояние сохраняется (ETag частей), поэтому перезапуск продолжает с недостающих частей. `client_id` делает `POST /recordings` идемпотентным — дубликатов нет. Presigned URL хранятся только в памяти; после перезапуска или истечения запрашиваются через `upload/parts`. Без сети очередь ждёт бесконечно (повтор до раза в минуту), ошибки сервера (5xx, 429) повторяются бесконечно с паузой до 5 минут; возврат в приложение и появление сети запускают ожидающие сразу. Отказ `upload/complete` разбирается по `details.reason`: `upload_incomplete` — повтор позже, `upload_parts_missing` — заново только перечисленные части, `upload_size_mismatch` — загрузка заново (сдаётся после 8 таких попыток), удалённая запись — ошибка; неизвестный 400 сохраняет ETag и повторяет `complete` без списка частей. Новый `upload_id` из `upload/parts` (сервер перезапустил умерший multipart) сбрасывает ETag. Неудачную загрузку можно «Сохранить на устройстве» (вернуть в локальный архив) или отменить; в обоих случаях текущий запрос прерывается, а пустая запись на сервере («Ожидает аудио») удаляется. Осиротевшие файлы в `pending/` удаляются при запуске.

На Android, пока идут загрузки, работает foreground service `UploadService` (dataSync) с процентом в уведомлении. Android 12+ не позволяет запускать его из фона — тогда очередь ждёт открытия приложения. Каждое обновление, включая финальное «0 загрузок», идёт через `onStartCommand`, поэтому сервис не остаётся висеть с уведомлением и wake lock.

## Записи организаций

Над списком записей — вкладки «На устройстве» и по одной на организацию (с числом незавершённых загрузок). Список — синхронизированные записи плюс ещё не дошедшие до сервера загрузки. Синхронизация — `GET /recordings/sync?cursor=` до `has_more=false`, курсор и записи хранятся на диске, так что список работает без сети: `library/<connection>/<org>/index.json` — только поля списка (без расшифровок), пишется один раз за синхронизацию; `items/<id>.json` — расшифровка, сегменты и выжимки одной записи, пишется только при её изменении или открытии. Сеть не держит блокировок. Обычные JSON-файлы вместо SQLite: это кэш, который сервер всегда восстановит, доступ — «список» или «одна запись», и не нужна новая нативная зависимость на четырёх платформах. Обновление — при открытии, возврате в приложение, раз в минуту при открытом списке и каждые 10 с у открытой записи, которая расшифровывается. Tombstones (`deleted_ids`) удаляют записи.

Экран записи: название, дата, длительность, проект, видимость, теги; карточка статуса (загрузка, «Расшифровывается 3/8», ошибка с «Повторить» → `POST /recordings/{id}/retry`); текст и «Выжимки» (`GET /recordings/{id}/results` при открытии, кэшируются; отсутствие обрабатывается).

## Аудио на устройстве

После загрузки аудио переезжает в кэш, после прослушивания скачивается туда же. Файлы, которые не открывали дольше срока «Хранить аудио на устройстве» (7/30/90 дней/всегда, по умолчанию 30), удаляются при запуске и раз в час. Текст и выжимки не удаляются. Desktop без кэша играет онлайн по presigned URL и параллельно кэширует; Android сначала скачивает (с процентом), затем играет системным плеером.

## Проверки

`cargo test --lib org::` — PKCE (вектор RFC 7636), валидация URL и версий, слияние sync/tombstones, машина состояний очереди, вытеснение кэша, воркер против встроенного фейкового сервера (multipart, сбой части, перезапуск без повторной отправки частей, кэш). Живой прогон против сервера: `HEARFOLIO_E2E_SERVER=… HEARFOLIO_E2E_EMAIL=… HEARFOLIO_E2E_PASSWORD=… cargo test --lib org_e2e -- --ignored --nocapture` (нужен пользователь с организацией и настроенный S3). Предпросмотр интерфейса: `npm run dev`, `?org=1` (и `&platform=android`).
