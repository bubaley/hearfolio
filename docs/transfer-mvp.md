# Передача записей: локальный MVP

Сервер пересылает аудио бинарными блоками по 64 КиБ. На диске сервера сохраняются только имена устройств, токены и связи между устройствами; аудио и расшифровки на диск не записываются. В памяти остаются метаданные активных передач и максимум один блок на передачу. Отправитель ждёт подтверждения записи блока получателем. «Доставлено» означает, что получатель проверил SHA-256 аудио и сохранил запись в свой архив.

## Проверка Linux → Android

1. Подключите ноутбук и телефон к одной Wi-Fi сети. Начните отправку и приём в приложениях. На Android активную передачу теперь можно продолжать после сворачивания и блокировки экрана; разрешите уведомления для отображения статуса и отмены.
2. Запустите сервер из корня репозитория: `npm run relay`. Node.js 22.12+; дополнительных npm-зависимостей серверу не требуется. Порт по умолчанию — 8787, адрес прослушивания — 0.0.0.0.
3. Узнайте локальный IP ноутбука: `ip -4 -brief address`. Для телефона используйте адрес Wi-Fi интерфейса, а не localhost или адрес Docker. На момент подготовки: `http://192.168.39.223:8787`; адрес может измениться.
4. Запустите Linux-сборку и установите тестовый APK на Android. На первом устройстве откройте «Настройки», задайте адрес сервера и имя устройства, затем нажмите «Подключить первое устройство к серверу». На локальном сервере без закрытой регистрации ключ можно оставить пустым; публичный сервер требует ключ администратора.
5. На первом устройстве откройте «Устройства»: справа сразу появятся QR и восьмизначный код. На телефоне нажмите «Сканировать QR» либо введите код вручную. При ручном вводе сначала сохраните тот же адрес сервера в «Настройках». Подтвердите запрос на первом устройстве. Общий ключ телефону не нужен; код одноразовый и действует 3 минуты.
6. Импортируйте или запишите аудио на ноутбуке. Расшифровка необязательна: если сохранённый результат уже есть, он будет отправлен вместе с аудио.
7. Откройте запись, нажмите кнопку «Поделиться» рядом с копированием и экспортом, выберите телефон. На телефоне откройте «Устройства» и нажмите «Принять запись», если автополучение отключено.
8. Дождитесь сохранения. Откройте полученную запись в архиве телефона: проверьте аудио, название и текст. Повторите отправку: неизменённая запись не должна создавать дубликат.
9. Проверьте обратную передачу Android → Linux. Во время отдельного теста разорвите сеть: запись отправителя должна сохраниться, незавершённая запись не должна появиться в архиве получателя. Повторную попытку можно запустить в «Устройствах».

## Границы MVP

- Передаются оригинальное аудио, текущая сохранённая расшифровка, название, даты, размер, длительность, модель и параметры распознавания. Локальные пути и OpenRouter API token не передаются.
- По умолчанию подключение и получение требуют подтверждения. В «Устройствах» доступны независимые переключатели автоматического подключения и получения от уже привязанных устройств. Привязку можно удалить с любого устройства.
- Максимум 1 ГиБ аудио и 4 МиБ текста, 16 активных передач на сервере, одна входящая передача на устройство. После 120 секунд без операций сервер очищает передачу и её буфер.
- Очередь отправителя хранит одну неотправленную запись и переживает перезапуск интерфейса. Повторная попытка начинается с начала; автоматического возобновления с блока пока нет.
- Идентификатор исходной записи сохраняется при пересылках. Возврат записи с новой расшифровкой обновляет текст, модель и дату результата в существующей записи; аудио и локальное название сохраняются. Пустой или более старый результат не стирает сохранённый текст. Перед пропуском аудио получатель заново считает SHA-256 локального файла. Повреждённый или отсутствующий файл получает полную проверенную копию с откатом при ошибке сохранения. Оба клиента должны быть обновлены; уже созданные старой версией дубликаты автоматически не объединяются.
- Сервер должен быть доверенным: HTTP разрешён только для локальных IP/localhost и подходит для домашнего теста; шифрования в этом режиме нет. Для внешнего сервера нужен HTTPS через обратный прокси. Сквозного шифрования пока нет.
- При разрыве после сохранения, но до подтверждения отправитель может показать ошибку; повторная отправка проверит дубликат.
- Доставка на выключенное устройство, несколько расшифровок и синхронизация удалений не включены. На Android активные передачи продолжаются в фоне; ожидание новых входящих включается отдельно в настройках. Встроенный QR-сканер доступен на Android; на десктопе используется ручной ввод кода или открытие ссылки приглашения.
- Не отправляйте приватные записи через HTTP в чужой сети. Токены хранятся локально в `transfer.json` и в серверном `work/relay/devices.json`; эти файлы не включаются в репозиторий.

## Сборка без системной установки зависимостей

Подготовленный контейнер содержит библиотеки Tauri и Java 21:

```sh
docker build -t hearfolio-transfer-build -f scripts/Dockerfile.transfer-build .
scripts/transfer-container.sh cargo test --locked --manifest-path src-tauri/Cargo.toml
scripts/transfer-container.sh npm run tauri -- build --debug --no-bundle --features transfer-mvp --config src-tauri/tauri.transfer.conf.json -- --locked
```

`transfer-container.sh` использует локальные Rust и Android SDK из `../../work/toolchains`; другое расположение задаётся через `HEARFOLIO_TOOLS`. Контейнер запускается с UID пользователя, не изменяет системные пакеты и сохраняет кэши в каталоге инструментов.

Для Android сначала нужны Rust target `aarch64-linux-android`, Android SDK 36, Build Tools 35.0.0 и 36.0.0 и NDK 27.2.12479018, затем:

```sh
scripts/transfer-container.sh npm run tauri -- android init --ci --skip-targets-install --config src-tauri/tauri.transfer.conf.json
node scripts/prepare-transfer-android.mjs
scripts/transfer-container.sh npm run tauri -- android build --ci --debug --apk --target aarch64 --features transfer-mvp --config src-tauri/tauri.transfer.conf.json
```

Тестовый Android-пакет — `com.bubaley.hearfolio.transfer`, он устанавливается рядом с обычным приложением. Linux-сборка с feature `transfer-mvp` использует отдельный архив `~/.hearfolio-transfer-mvp` и настройки `~/.config/HearfolioTransferMVP`. Обычный архив не переносится. Автоматические обновления в тестовом варианте отключаются в интерфейсе.

## Проверки

```sh
npm run build
npm run test:transfer
node --test scripts/release.test.mjs scripts/prepare-android.test.mjs
scripts/transfer-container.sh cargo test --locked --manifest-path src-tauri/Cargo.toml
```

Серверные тесты проверяют привязку, одноразовые/просроченные коды, ограничение попыток, доступ непривязанных устройств, пересылку бинарных блоков, ожидание подтверждений, отмену и некорректные смещения. Rust-тесты проверяют импорт аудио и метаданных, повторное получение и откат при ошибке записи архива с сохранением посторонних файлов.

В разделе «Устройства» слева показаны устройства, справа сразу отображаются QR и код. Также новое устройство можно подключить из окна «Поделиться»: QR содержит адрес сервера и одноразовый восьмизначный код (3 минуты). Android открывает приглашение через схему hearfolio-transfer и предлагает подтвердить подключение; ручной ввод кода доступен для камер, которые не открывают ссылки приложения. После запроса подтвердите подключение на устройстве с QR. Окно использует оформление текущих диалогов Hearfolio.

Для новых устройств адрес сервера по умолчанию — `https://hearfolio.corextech.ru`. Сохранённый пользовательский адрес имеет приоритет; локальные экземпляры продолжают использовать свой LAN-сервер.

## Подключение по приглашению

Адрес сервера, имя устройства и ключ администратора находятся в «Настройках». Общее разрешение на регистрацию нужно только первому устройству: введите ключ и подключите его к серверу. Затем в «Устройствах» создайте QR/код. Новое устройство сканирует QR либо вводит код в «Устройствах» и своё имя. Общий ключ вводить не требуется. До подтверждения на приглашающем устройстве токен не выдаётся; настройка автоподключения подтверждает такие запросы автоматически. При ручном вводе кода оба устройства должны использовать один сервер. Для другого адреса сначала сохраните его в «Настройках».

Для публикации Docker-образа бэка подготовлен `.github/workflows/docker.yaml`, подробности в `server/deploy/README.md`.

## Сканер Android и совместимость метаданных

В разделе «Устройства» и окне подключения доступна кнопка «Сканировать QR». Используется камера внутри приложения, с запросом разрешения и возможностью закрыть сканер; произвольные QR не открываются как ссылки. После чтения приглашения пользователь подтверждает сервер и имя устройства. Ручной ввод кода остаётся доступен.

Проверка переносимых метаданных отделена от проверки доступности модели на получателе. Android принимает аудио, готовую расшифровку и информацию о локальной модели десктопа, хотя повторный запуск локального распознавания на Android недоступен.

Пользователь подтвердил работу камеры и полного сценария передачи на физическом Android.

## Фоновая передача Android и экономия трафика

Пользователь запускает отправку или принимает предложение в открытом приложении. Затем foreground service типа dataSync поддерживает работу нативного Rust-потока при сворачивании и блокировке экрана. Уведомление показывает общий статус/процент и кнопку отмены, без названия записи и текста расшифровки. Android 13+ запрашивает доступ к уведомлениям; при отказе сервис может продолжать работу, но уведомление и действие на экране блокировки недоступны. Сервис и CPU/Wi-Fi locks снимаются после завершения или ошибки, собственный предел операции — 2 часа. Принудительная остановка приложения или перезагрузка не поддерживают продолжение передачи. Дополнительные ограничения производителя телефона и Android требуют проверки на реальном устройстве.

Перед приёмом клиент проверяет файл соответствующей исходной записи по фактическим размеру и SHA-256. Новый отправитель и relay согласуют audioRequired=false только при совпадении; по сети идут расшифровка и метаданные. Для отсутствующего/повреждённого файла передаётся аудио полностью, проверяется SHA-256 и восстанавливается существующая запись без дубликата. Старые отправители/relay используют полную передачу.

Проверка на телефоне: обновить оба клиента; отправить длинную запись, принять на Android и свернуть приложение/выключить экран. Проверить сохранение, статус и отмену в уведомлении. Повторная отправка новой расшифровки должна пройти без аудиоблоков. Повреждённую копию следует проверять только в отдельном тестовом архиве: повторная передача должна восстановить аудио. Android foreground service описан в https://developer.android.com/develop/background-work/services/fgs/service-types.

## Запись и получение при заблокированном Android

- Начните запись в приложении и разрешите микрофон/уведомления. В уведомлении на экране блокировки доступны «Пауза», «Продолжить» и «Сохранить». Сохранение сразу добавляет аудио в архив; после возврата в приложение результат доступен для расшифровки. Запись ограничена четырьмя часами, затем сохраняется автоматически.
- В «Настройки → Передача между устройствами» включите «Ожидать передачи в фоне». Появится постоянное уведомление с кнопкой «Выключить». Ожидание использует заряд; принудительная остановка Android останавливает сервис. При следующем запуске приложения сохранённая настройка может включить его снова.
- С включённым «Получать файлы без подтверждения» запись принимается и сохраняется нативным кодом даже при свёрнутом WebView. Во время записи/распознавания входящая передача ждёт освобождения приложения. Без автоматического приёма уведомление предлагает открыть приложение и подтвердить передачу.
- Настройка автоматического подключения устройств также применяется в фоне; по умолчанию обе автоматические настройки выключены. Имена файлов, расшифровки и ключи не отображаются на заблокированном экране.
- Проверка на телефоне: запустить запись, заблокировать экран, поставить на паузу, продолжить, сохранить; затем проверить аудио в архиве. Включить фоновое ожидание, свернуть приложение и отправить запись с Linux — проверить автоматический приём, затем повторить с отключённым автоприёмом и подтвердить через приложение. Отдельно выключить ожидание из уведомления.

Нативные сервисы объявлены как `microphone` для записи, `connectedDevice` для связи с сопряжёнными внешними устройствами по сети и `dataSync` для отдельно начатой передачи. Правила Android: https://developer.android.com/develop/background-work/services/fgs/service-types.

## Плитка записи Android

После установки откройте редактирование плиток шторки и добавьте «Запись Hearfolio». Нажатие открывает отдельный нативный экран над блокировкой и начинает запись, даже если основное приложение не запускалось. При первом использовании нужно разрешить микрофон; если телефон заблокирован и разрешение ещё не выдано, сначала потребуется разблокировка.

Повторное нажатие показывает управление уже идущей записью. Доступны таймер, пауза, продолжение и сохранение. Закрытие этого экрана не останавливает запись; управление остаётся в уведомлении. Архив и расшифровки в этом окне отсутствуют. Записи, начатые плиткой, сохраняются в приватной папке приложения и автоматически добавляются в архив при следующем открытии Hearfolio. Незавершённые файлы не импортируются; стабильный идентификатор защищает повторный импорт от дубликатов.

Проверка на телефоне: добавить плитку, закрыть Hearfolio, заблокировать экран, нажать плитку, записать аудио с паузой, сохранить, открыть приложение и проверить одну запись в архиве. Повторное открытие приложения не должно добавлять дубликат. Поведение плитки над блокировкой зависит от настроек производителя телефона.

### Ярлык в углу экрана блокировки

Редактор угловых ярлыков экрана блокировки и редактор плиток шторки — разные механизмы. Плитка находится в шторке быстрых настроек. Для редактора, показанного на телефоне, добавлен отдельный запуск «Запись Hearfolio» в списке приложений: он открывает компактный экран и начинает запись, а основной ярлык Hearfolio открывает полный интерфейс.

После обновления APK заново выберите в редакторе блокировки «Приложения → Запись Hearfolio» (значок микрофона). Разрешите микрофон при первом запуске на разблокированном телефоне. Запись запускается над блокировкой, если прошивка разрешает запуск выбранного приложения без разблокировки. Само приложение не может гарантировать это для редактора производителя; если система требует разблокировать телефон, используйте плитку шторки. В список встроенных системных действий приложение этой доработкой не добавляется.

Пауза и продолжение в уведомлении теперь синхронизируются с основным экраном при возвращении в приложение и во время работы интерфейса. Состояние и таймер считываются из нативного сервиса; это также относится к записи, начатой плиткой или ярлыком. В приложении такую запись можно остановить и сохранить либо отменить. Уже открытая несохранённая расшифровка сохраняется в интерфейсе при добавлении новой записи в архив.

### Индикатор микрофона

На основном экране и на компактном экране записи над блокировкой добавлены три едва заметные плавные волны на фоне таймера, которые реагируют на реальную громкость микрофона. Мягкое свечение и затухающие края сохраняют читаемость экрана. В тишине индикатор остаётся ровным, при паузе и остановке замирает. Android использует уровень из сервиса записи; Linux — из записываемых аудиосэмплов. Ярлык «Запись Hearfolio» получил отдельный контрастный значок: белый микрофон на тёмном фоне. Реакцию на голос на физическом Android ещё нужно проверить.
